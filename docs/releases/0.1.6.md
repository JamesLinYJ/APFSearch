# APFSearch 0.1.6 Preview

这次更新集中改进索引的内存布局、持续更新与搜索窗口的生命周期，并修复 GitHub 下载版未采用新版 macOS 控件外观的问题。

- 文本块共享内容完全一致的目录前缀，保留连续的文件名搜索区域。读取仍直接访问字节区间，不在每次查询时重新展开全部路径。
- 倒排索引按分片共享，名称与路径排序改为共享叶块；增量更新仅修改变化的词项和排序区段，减少旧快照与新快照之间的复制。
- 搜索取消时保留屏幕上结果的快照，等新结果接替后再释放；关闭窗口会丢弃并释放迟到的响应。离线列表按请求、快照和导出的实际生命周期管理。
- 索引打开失败会提供明确的重试入口，不再误导到后台服务权限设置。文本内容提取可在分块读取之间响应取消。
- GitHub Actions 使用 macOS 26 SDK 或更新版本构建，并逐个验证应用、服务、CLI 的架构切片。支持的系统可使用原生 Liquid Glass，最低运行版本仍为 macOS 14。

**升级说明：** 保留 SQLite 索引、配置、公开查询接口及协议。内部构建号仍为 1；派生缓存更新到格式 04，首次启动从已有 SQLite 重新生成，不因缓存升级重新扫描文件系统。首次转换有一次性的时间和写入成本。

这是阶段性开发预览版，未宣称达到整个进程内存下降 40% 的目标。结构载荷、RSS 和物理内存占用是不同指标；隔离查询与更新测试也不代表所有机器和整盘工作负载。实现及可复现对照工具见[技术记录](https://github.com/JamesLinYJ/APFSearch/blob/v0.1.6/docs/SNAPSHOT_SHARING.md)。真实 Intel 硬件、最低系统版本和长期整盘负载仍需验证。

提供 **Apple Silicon、Intel、Universal** 三种架构，各有 DMG 和 ZIP。应用及 DMG 通过 Developer ID 签名和 Apple 公证；ZIP 包含已装订公证票据的应用。

---

This checkpoint improves index storage, incremental updates and search-window ownership, and fixes the older system appearance of GitHub builds.

- Share byte-identical directory prefixes within text blocks while retaining contiguous search names. Queries continue reading direct byte ranges without expanding every path.
- Share posting shards and ordered leaves across snapshots. Update only changed terms and order sections instead of copying entire auxiliary indexes.
- Keep displayed results leased until their replacement succeeds; retire late responses after a window closes. Imported indexes follow active request, snapshot and export lifetimes.
- Offer an explicit retry for index-open failures instead of directing users to background-service permissions. Text extraction responds to cancellation between bounded reads.
- Build with macOS SDK 26 or newer in GitHub Actions and verify every app, service and CLI architecture slice. Native controls adopt Liquid Glass on supported systems; macOS 14 remains the minimum runtime.

**Upgrading:** SQLite data, settings, public queries and the protocol are preserved. The internal build number remains 1. Derived caches use format 04 and are regenerated from existing SQLite on first launch, without a filesystem rescan caused by the cache upgrade. This conversion has a one-time time and write cost.

This is a staged development preview, not a claim of reaching the 40% whole-process memory target. Structural payload, RSS and physical footprint are different measurements; isolated query/update comparisons are not whole-machine guarantees. See the [implementation and reproducible comparison tools](https://github.com/JamesLinYJ/APFSearch/blob/v0.1.6/docs/SNAPSHOT_SHARING.md). Physical Intel hardware, the minimum OS and long-running full-volume workloads still need validation.

Choose **Apple Silicon, Intel or Universal**, as DMG or ZIP. Apps and DMGs are Developer ID signed and Apple notarized; ZIPs contain the stapled application.
